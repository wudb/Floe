# 可靠布局与异常恢复

日期：2026-10-23（Asia/Shanghai）。修改基线：`a891d92`。

本批状态：**原生窗口布局恢复代码已实现，受控回归已验证；真实系统场景验收待补**。
不据此关闭上游报告，也不调整原清单 367 条或 M2 63 条的保留数量。

## 用户入口

设置 → 菜单栏布局 → **布局恢复 → 恢复已保存布局**。

- 重放已保存的图标分区和顺序，不改其他偏好，不把当前异常布局保存成新布局。
- 支持取消；离开页面同样取消。取消后不继续后台执行这批显式恢复。
- 分别显示完成、尚有待恢复项、取消、读取失败、模式不支持、记录损坏和没有记录。
- 原有顶部刷新入口重新发现当前项目；刷新不等于保存或重放布局。
- 未运行的宿主保留分区及相对排序锚点；稍后重新出现时可继续恢复。

这是对已有本机布局持久化的补强，不包含整套配置导入导出或历史版本备份。

## 修复内容

1. 将已观察身份与待完成项目分开。输入等待中取消、窗口元数据暂不可用或分隔符缺失，不再让项目永久失去重试机会；失败后保留 30 秒退避。
2. 身份同时比较宿主 PID 与窗口 ID，每次投递前重新解析来源及锚点；同名歧义项目保守跳过，不猜测其身份。
3. 用户新拖拽、规则变更和环境变化会使旧事务失效。等待用户松开输入后，以及每次重试投递前，重新核对事务，取消路径不会触发唤醒重试。
4. 第一项无法进入目标分区时，停止依赖它的后续移动，避免把后续项目拖入错误分区。暂时禁用的始终隐藏分区保留待办。
5. 原生移动以目标邻项的位置验证成功；单纯坐标变化不再被当作完成。指针与事件监听的清理仍覆盖成功、失败和取消路径。
6. 监听休眠、唤醒、显示器和 Space 变化；取消过时恢复，失效缓存，合并 700 毫秒内的环境变化后强制读取。休眠期间不启动扫描。
7. 强制扫描只有成功发布的快照才能满足等待者；失败扫描不能冒充刷新完成，显式恢复也必须读取新快照。分隔符自动归位后重新读取边界。
8. 校验存储的键、分区及唯一性，损坏记录不被后台初始化或新图标规则静默覆盖；显式手动整理成功后才能保存新布局。

## 验证与边界

`script/tests/layout-persistence.swift` 编译生产存储及恢复入口、环境协调方法，使用内存偏好和受控移动服务验证取消续作、用户选择优先、失败锚点、PID/窗口复用、分隔符恢复、退出宿主排序、坏数据保留、显式取消、环境事件合并及休眠/唤醒。

`item-discovery.swift` 覆盖并发强制刷新、失败扫描、旧环境快照丢弃及休眠暂停；`layout-native-pointer.swift` 覆盖错误落点拒绝、等待后事务失效，以及指针和监听清理。连续拖拽、键盘整理、AX 取消、浮栏重排、语言与紧凑布局沿用现有回归。

当前主机为 macOS 15.8.1。测试不发送真实拖拽、不改系统授权、不安装或启动新构建。
