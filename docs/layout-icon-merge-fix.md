# 菜单栏布局重复图标与跨分区移动修复

日期：2026-10-19。

## 已确认的代码问题

- 布局页同时合并 CGS 与 AX 来源，旧判断要求中心误差不超过 1 点、尺寸误差不超过 2 点。AX 内部图片/按钮通常比 CGS 窗口小，这类同位置图标会重复出现，甚至显示图片资源名。
- 布局页统一使用坐标 Command-drag。空隐藏区相邻分隔符之间的中点可能落在分隔符内部，不能可靠表示“放到此分区”。

## 修改

- 同一宿主已由 CGS 窗口快照覆盖时，以该宿主的 CGS 列表为准；AX 仅补充尚未发现的宿主，避免 AX 按钮/图片代理与原生窗口重复。CGS 内真实多图标不合并。跨宿主代理仍按唯一几何位置匹配。
- AXButton 作为可操作状态按钮直接记录，不再下钻到其 AXImage 子节点并显示图片资源名。
- CGS 项目复用原生 `MenuBarItemManager.move`，以真实窗口及分隔符/目标项目身份插入。隐藏区放在隐藏分隔符左侧，始终隐藏区放在对应分隔符左侧，可见区放在隐藏分隔符右侧。原生移动失败不退回不可靠坐标，也不伪报成功。
- AX-only 或混合来源排序继续使用坐标回退，要求起终点在同屏且位于同一菜单栏行。合成拖拽前等待用户释放真实鼠标和修饰键；移动后仍重新扫描并核对真实分区/顺序。

## 验证边界

生产方法的受控回归覆盖内缩/垂直偏移边框、相邻同名项、未知项保留、空分区原生插入、排序、宿主身份不匹配、移动失败及屏外 AX 拒绝。54 个 Swift 回归全部通过，严格 SwiftLint 通过；开发签名 Debug/Release 构建通过。

截图中的真实第三方图标移动仍需重新运行修复后的构建验收；本次未自动操纵用户真实菜单栏，也不将受控环境测试记作原报告已验收。

## 2026-10-19 后续：刷新回跳与分区不一致

- 布局页直接消费 `@Published itemCache` 回调并同步读取属性时可能读到旧值。改为在主队列接收后重建视图，确保缓存已提交。
- CGS 项目使用 `itemCache.section(for:)` 的真实分区，与普通浮栏共用结果；不因 UI 层 AX 分隔符缺失而重新判为全部可见。
- CGS 可用时布局页不再每五秒发起一次完整刷新。AX-only 后台扫描保留，但不显示手动刷新进度。手动刷新仍有并发保护。
- 拖动成功后的最终扫描、确认和记录结束前保持 `isMoving` 与编辑保护，避免后台更新抢占收尾阶段。
- AX-only 且无法确认边界时显示“分区未确认”，不再把未知项目宣称为可见，也不把未知的隐藏区域宣称为空。

本次对已安装 `/Applications/Floe-Dev.app` 执行了只读诊断，返回辅助功能与屏幕录制预检均为 false，且探测时未发现运行中的 Floe 管理进程。因此没有用该状态推断截图时的授权，也没有声称已实机复现完整拖动或通过原场景验收。未重置权限、未自动移动真实图标。

## 普通点击分区与拖动扫描开销

进一步截图表明，浮栏四项对应“始终隐藏”区。原因是 `ControlItem.performAction` 在启用始终隐藏分区时把主图标普通点击改成了始终隐藏操作。现恢复普通点击控制隐藏区、Option 点击控制始终隐藏区；AX 浮栏有可用边界时严格按请求分区过滤，不再混合两类隐藏项目。

拖动读回在有 CGS 项目时保留已有 AX 补充快照，不再重新遍历每个应用的辅助功能树。成功后的最终确认复用读回方法，取消旧的完整刷新及等待流程。页面初次扫描的分隔符等待仅保留给 AX-only 情况。拖动进行中保留图标透明度与 moving 提示，移除每次移动都出现的旋转圆圈。

这些变化减少重复发现工作；真实原生移动与读回依然异步执行，未记录成功前不会伪报完成。本次没有对用户菜单栏主动执行计时拖拽，不能声称已实测所有第三方图标的延迟。

## 2026-10-20：拖拽反馈迟滞与反复刷新

用户反馈每次移动仍有明显迟滞，且需要手动刷新。进一步确认以下代码路径：

- 即时布局直接写入真实分组，物理移动结束后又恢复旧快照，再进行位置读回，导致回跳。
- 正常原生移动路径重复执行移动前扫描、额外强制缓存、落点扫描与成功后的重复扫描，并且可见区排序也无条件展开隐藏区、等待 250 ms。
- 强制缓存遇到另一轮扫描时仅安排后续任务便返回，调用方的 await 没有等到新快照。
- 临时展开的分区在最终扫描之后才于 defer 中收起，收起造成的位置变化没有再次读回。

修改后，临时 movePreview 与真实 sections 分离，落点立即显示且不参与成功判定；原生路径按身份读取实时窗口，去掉移动前的重复扫描。可见区内排序不展开隐藏分区；正常落点只做一次确认。帧未稳定时只做有界读回；每次设置页操作只发送一次系统移动。收起临时分区后继续确认，结束后再释放编辑保护；失败时显示真实快照。

同区空白处放下及已相邻的目标位置直接结束，避免无效移动和重排。分区落点预览匹配原生分隔符插入位置：可见区插入最左端，隐藏分区插入最右端。强制缓存等待请求发起后启动的新扫描完成，并与同时等待的强制请求共享结果；普通后台触发仍合并，取消等待不影响正在执行的其他请求。

生产流程的受控回归覆盖即时预览、真实位置隔离、一次原生读回、晚到帧、失败回滚、同区无操作、收起后的读回保护、取消，以及强制缓存并发与取消。8 项相关回归（item-discovery、layout-drag-reveal、layout-native-move、layout-drop-order、layout-refresh-state、layout-cache-fallback、layout-keyboard-actions、layout-persistence）、严格 SwiftLint、Debug 构建和 git diff --check 通过。已用原开发证书和 ./script/dev.sh 更新、启动 /Applications/Floe-Dev.app。实际第三方菜单栏图标的手感与耗时仍需在用户主机复测，未主动模拟鼠标拖动真实图标。

## 连续拖拽时的鼠标冲突

用户进一步确认：上一项放下后，整个后台操作期间指针会闪动且无法继续拖动。只在整个同步期间禁用拖拽源虽然避免了重叠，却没有解决操作体验。源码还显示原生移动把指针送到屏外、再恢复原处，且布局页的外层重试与管理器的最多五次重试会叠加。

- 连续放下按顺序排队，queuedMovePreview 立即显示全部待执行落点；真实 sections 仍只用于系统位置确认。后台扫描和落点确认期间可以继续拖动，只有实际发送系统鼠标事件的事务暂停新拖拽。
- 每次确认后用真实快照重算剩余预览；前项失败不会把预览当作成功结果。页面关闭取消工作并清除队列。系统移动保持串行执行。
- 等待真实鼠标释放、修饰键松开和指针静止的阶段不锁住拖拽入口；管理器在发送事件前才通知布局页进入指针事务，并再次检查真实鼠标按下，避免后续按下被合成 mouseUp 打断。
- 设置页原生移动最多一次物理尝试，取消外层物理重试；帧延迟只重试读取。其他自动恢复调用保留原有有界重试。
- 原生与 AX 事务隐藏合成轨迹，所有退出路径先恢复原位置再配对显示指针；隐藏失败时不减少隐藏计数。AX 释放按键后的额外 350 ms 等待交给位置确认，缩短指针占用。
- 每次拖拽使用独立的一次性 token；旧来源、重复 provider 回调及关闭页面后的迟到回调不能加入队列。
