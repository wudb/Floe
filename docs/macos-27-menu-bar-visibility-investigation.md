# macOS 27 菜单栏图标排查与恢复

## 用户反馈与未确认项

2026-10-26 收到反馈：macOS 27.0.1 上 Wi‑Fi 图标不显示、无法显示菜单栏项目、Floe 自身图标不显示。

尚未确认退出 Floe 后系统图标是否恢复；反馈用户的 Floe 版本、是否使用刘海屏/外接显示器/全屏，以及实际日志仍待补充。因此本记录不把三个现象直接归为同一根因，也不宣称已修复该用户的原始故障。

2026-10-26 排查时，本机为 macOS 15.8.1，Xcode 26.3 / SDK 26.2，当时无法验证 MenuBarAgent 的真实布局行为。升级后的实机记录见下文。

## 已核对的源码与问题

- 基线：`wudb/Floe` 的 `0086dbe`，现有发布 v1.0.2 已有“恢复 Floe 图标”入口和 macOS 27 首次展开迁移，但没有持久到本次运行结束的菜单栏可见性恢复模式。
- 直接上游：`cavaldos/Ice` 的 `82be80fea77edd89f34a43ddfbc677234a416dee`（2026-10-10）。已直接读取其 `Ice/MenuBar/ControlItem/ControlItem.swift`；Floe 继承了相同的 `regionWidth - 32` / 无屏幕时固定 1,000 点占位宽度算法。不是因为缺少某个 PR 就判定其完全不支持 macOS 27。
- 原始上游：[jordanbaird/Ice#995](https://github.com/jordanbaird/Ice/pull/995)，核对时为 open，head `98b38a39fce11216e645a2022d9be58a55e7e272`。该 PR 针对 MenuBarAgent 的读取、隐藏和系统图标交互提出另一套路径；不能把 Floe 的现有 AX 回退视作已集成该完整方案。
- [jordanbaird/Ice#1006](https://github.com/jordanbaird/Ice/issues/1006) 记录 macOS 27.0.1 上的空布局、窗口位置与身份/签名差异。它是相似报告，不是本次用户故障的复现证据。
- [CleanMenuBar 实测说明](https://github.com/atilac/CleanMenuBar#how-macos-27-broke-the-old-approach) 描述 macOS 27.0 的半屏宽度临界行为。本批据此增加上限防护；该测量不能代替 Floe 在 27.0.1 上的验收。

### 代码层面的确定缺口

1. “恢复 Floe 图标”只切换自身可见性及 `SItem` 的首选位置，不释放 `HItem` / `AHItem` 的隐藏占位。它无法作为被隐藏系统图标的统一恢复入口。
2. CGS 不可用后，浮栏依赖 AX 返回项目；如果项目已隐藏且 AX 不返回，刷新列表本身不能使其重新出现。使用浮栏时原有代码还会有意保持原生占位项展开，不能把浮栏刷新当作恢复原生可见性。
3. 非刘海屏的 `regionWidth - 32` 可能达到半屏以上；缺失屏幕时固定 1,000 点也没有几何保证。屏幕切换/唤醒没有重新计算占位宽度的订阅。
4. 折叠分隔符使用窗口私有约束和 `setContentSize`。macOS 27 的共享菜单栏窗口下，继续假定窗口只属于单个状态项有风险；这一点仍需真机确认影响范围。
5. 无效自定义图像可能得到 nil/零尺寸图像，使恢复自身位置之后仍没有可见图形。

## 本批实现

- 通用设置增加“恢复菜单栏项目”。通过 Floe 自己的公开状态项长度接口释放两处隐藏占位，并恢复 Floe 图标；无需 CGS/AX 成功扫描第三方项目。
- 本次运行暂停隐藏占位和自动布局移动，取消旧恢复任务。换屏、切换 Space、休眠与唤醒不能解除暂停；重复恢复不覆盖最初分区状态。
- 保留已保存布局和隐藏偏好，不修改系统 Wi‑Fi、控制中心或 TCC 设置。用户可“继续隐藏”，或重启退出本次恢复模式。
- macOS 27 不再修改状态项窗口的私有约束和尺寸；未显示的分隔符使用公开的 1 点长度。占位宽度取所有屏幕限制的最小值，严格小于任一有效屏幕点宽度的一半；未知/无效几何回退 1 点，优先保持可见。
- 换屏、唤醒与 Space 切换后重新计算宽度。无效自定义图像在绘制时回退内置图形；恢复期间固定使用内置图形以排除透明自定义图像，继续隐藏后还原原选择，不覆盖用户图像数据。

### 修正与依据

- AX 缓存为逻辑项目分配会话内稳定 ID。单项目宿主切换 AX 表示时更新操作目标，多项目宿主按精确元素或唯一系统标识匹配。界面、拖拽队列和浮栏使用该稳定 ID，避免旧来源与新代理同时成为两行。
- 已确认的分区在收起状态保留，展开时使用真实扫描更新。移动成功由展开后的实时分区和顺序确认，收起后的缺失或系统占位坐标继续使用已确认记录。
- 原生分隔符长度落地后，再临时展开系统溢出区并读取坐标。完成或取消时收回本次展开。投递 Command-drag 前，在主线程核对坐标实际命中的 AX 元素或进程，防止把共享占位帧当作另一应用的拖动起点。
- 始终隐藏分隔符进入系统溢出区时，从代理菜单栏窗口补读其精确标识。分隔符与溢出按钮遍历均有时间和节点上限。启动快照等待状态项与溢出区展开稳定后读取边界。
- 隐藏分区的空白落点紧邻其右侧分隔符。两条分隔符处于刘海两侧时，原先取中点的算法可能落入不可交互区域。
